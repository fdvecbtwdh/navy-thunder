# Navy Thunder

[![CI](https://github.com/fdvecbtwdh/navy-thunder/actions/workflows/ci.yml/badge.svg)](https://github.com/fdvecbtwdh/navy-thunder/actions/workflows/ci.yml)

一款正在开发中的**单机二战海战游戏**（PvE）：玩家操纵真实历史舰船与 AI 舰队交战，战斗机制以 War Thunder 海战为基准，舰船建造以 NavalArt 为理念基准，首发**美 / 日 / 英 / 德**四阵营。

> 本 README 是**项目现状说明**（2026-10-05 全仓核查后重写）：它描述的是当前仓库里真实存在的东西，不是开发计划。计划与缺口见 [开发路线](#开发路线) 与 `docs/phases/`。

---

## 游戏简介

Navy Thunder 的差异化定位是三方经验的融合：

| 维度 | 来源 | Navy Thunder 的选择 |
|---|---|---|
| 战斗数值 | War Thunder（官方公式 + 客户端实测数据） | 穿深用官方 de Marre 公式，弹道对官方射表校准 |
| 舰船建造 | NavalArt（方块拼船、物理沉没） | 建造器产出与史实舰同构的数据，走同一套战斗系统（尚未实现，已立项） |
| 独有价值 | — | **全模拟确定性**：同种子战斗可逐字节重放（WT 与 NavalArt 都不具备） |

**船不是一个大血条。** 每艘船内部是几十个三维摆放的舱室与部件（弹药库、主机、锅炉、扬弹机、舵机、火控、水泵、烟囱……），炮弹穿甲后沿弹道在舰体内部继续破坏，由此产生起火、进水、倾斜、殉爆、倾覆等连锁后果——这是本项目最核心、最扎实的系统。

## 核心玩法

一场标准的遭遇战：

1. 从主菜单的 30 艘真实舰船（驱逐舰 → 战列舰）中选一艘；
2. 进入 3D 海面，操舵、控制油门，与敌舰机动占位；
3. 用两档火控瞄准：**自动档**（锁定目标 + 试射自动修正 + 提前量指示）或**手动档**（光标选落点 + 滚轮调距离）；
4. 按需切换穿甲弹（AP）/ 高爆弹（HE），观察命中反馈（击穿 / 跳弹 / 过穿 / 未穿 / 水柱）；
5. 中弹后通过损管面板指挥灭火 / 堵漏 / 排水，调整优先级；
6. 一方全灭即胜，或到时限判平局；结束后查看战报（每艘船的结局与死因）。

## 玩家现在可以做什么

以下全部是**现在打开游戏就能用**的功能：

- 主菜单：选舰（30 艘，四阵营）、设置（主/效果/环境音量、键位重绑定、简体中文/English）、开始战斗、退出；
- 操舰：W/S 油门（连续，无档位与倒车）、A/D 转舵、X 舵回中；
- 火控：G 切换自动/手动瞄准、T 锁定目标、R 切换 AP/HE、滚轮调瞄准距离；
- 损管：面板点击切换自动/手动模式、三档优先级预设（修理/灭火/排水）、单独启用每条流程；
- 战术地图（M 键全屏，含本舰/锁定目标/敌我标记）、暂停菜单（ESC：继续/重开/回主菜单/退出）、追击相机与自由观察相机（F）；
- 开场教学提示卡与底部键位提示，全 UI 双语。

**目前做不到的**：选择战斗规模/地图（固定 1v1 + 双方各 1 架 AI 飞机）、发射鱼雷、控制飞机、观战模式、战斗加速、倒车、"再来一局"按钮（需经暂停菜单重开）。

## 当前战斗系统

| 系统 | 状态 | 说明 |
|---|---|---|
| 舰炮 | 已实现 | 装填循环、弹药消耗、齐射散布（弹着沿目标舰体分布）、一级弹药打空后 35 秒从弹药库补给、炮塔被毁停射 |
| 弹道 | 已实现 | 逐弹重力 + 阻力积分，对官方射表校准 ±3% 内 |
| 穿甲 | 已实现 | 官方 de Marre 公式 + 转正/跳弹/碾压（overmatch），击穿后剩余穿深决定舰内破坏路径 |
| 装甲与命中 | 已实现 | 舷侧/甲板/艏艉隔板数据化，命中判定随船朝向真实旋转（打船头和打舷侧结果不同） |
| 模块损伤 | 已实现 | 扬弹机损→装填变慢、舵机损→卡舵漂航（可修理）、火控损→散布变差、烟囱损→掉速、主机/锅炉损→动力下降 |
| 起火 | 已实现 | 中弹掷骰起火，沿"炮塔→扬弹机→弹药库"蔓延，损管可扑灭，进水淹火 |
| 进水 | 大部分实现 | 破口三分类（炮弹/爆炸/鱼雷）+ 水泵排水 + 浮力结算。**已知缺陷：炮弹动能小破口的进水路径断线（见已知不足）** |
| 防雷隔舱（TDS） | 已实现 | 大型舰防雷凸舱吸收鱼雷水下爆炸，超限被摧毁后失效 |
| 弹药库殉爆 | 已实现 | 弹药库被毁即殉爆，威力随剩余弹药变化，可一发击沉 |
| 横倾与沉没 | 已实现 | 单侧进水→船体倾斜→超过临界角倾覆；六种击沉判定（舰员丧失/自沉/沉没/丧失不沉性/倾覆/殉爆），沉没带倾斜下沉动画 |
| 鱼雷 | 部分实现 | 雷体与水中冲击机制完整，但当前**只有 AI 飞机能空投**；舰上没有鱼雷管数据，玩家不能发射 |
| 防空 | 已实现 | 防空炮按舰船数据挂载，对空近炸弹幕。小缺陷：雷达加成未接线，命中恒按较差档计算 |
| 航空 | 部分实现 | 简化飞行模型 + 雷击/俯冲任务链 + 目标死亡重定向；仅 1 个机型、无航母、玩家不可控 |
| 导弹 | 尚未接入 | 制导代码在库，未接入战斗、无数据，游戏中不存在 |
| 胜负与战报 | 已实现 | 歼灭战 + 时限平局；战报含胜负/时长/损失/齐射数/逐舰死因。缺陷：战报中"承受伤害/命中数"两栏无写入（恒为 0） |

## 舰船与历史数据

- **30 艘可玩舰**（美 18 / 日 6 / 英 3 / 德 3），全部为真实舰名：依阿华、俾斯麦、长门、弗莱彻等。排水量、航速、主炮射速、弹重、初速等主要数值取自 War Thunder 客户端实测参数；舱室布局按舰级模板生成（战列舰约 25 舱、驱逐舰约 14 舱），装甲板为每舰独立厚度的舷侧/甲板/艏艉隔板三件套——**逐舰对照史实装甲图的手工建模尚未做**。
- 数据底座：**2,322 艘** War Thunder 舰船单位参数已提取入库（`data/reference/`），36 个弹种、九三式氧气鱼雷；数据逐项标注来源与可信级别，官方未公开的参数显式标记为近似（16 份机制决策记录见 `docs/mechanisms/`）。
- 内部结构（舱室/部件/装甲）与外观模型是**两套独立数据**：命中判定用的是简化盒体数据，不是视觉网格——这与 War Thunder 的做法一致。

## AI

**如实评价：会打，但不太聪明。**

AI 已经可以完成基本的航行、目标选择（威胁加权）、抢占横舷位、"之"字规避、按射程与射界纪律开火；飞机能执行完整的雷击/俯冲任务链并在目标死亡后自动换目标。AI 与玩家走**完全相同的指令接口**，无作弊、无信息特权。

但战术决策仍较简单：没有编队协同、没有目标分配与集火、AI 水面舰不会使用鱼雷、飞机没有空战格斗、受损后也不会聪明地调整损管优先级（该项因接线缺陷暂未生效）。距离"编队能打"的战术 AI 还有整个 Phase 07 的距离。

## 音效

区分两层，如实记录：

- **音频系统（播放机制）：已可用**——战斗事件（开炮/命中/爆炸/殉爆/沉没）驱动播放，按口径选音色，距离衰减，三路音量总线（主/效果/环境）接设置界面。
- **实际音频资产：明显不足**——所有声音都是**程序实时合成的电子音**（低频正弦+噪声近似炮声、8 秒循环合成海浪），没有任何真实录音或提取音源；无音乐、无 UI 音效、无飞机/火灾/进水专属音效。真实音源（War Thunder 音频库解析或自有素材）已立项为正式开发项。

## 舰船建造系统

**目前玩家不能造船——建造器代码为零实现**，是项目最大的功能缺口。已完成的准备：完整设计文档（对标 NavalArt：方块船体、逐块装甲、质心/浮心指示器）、战斗引擎的舰船数据格式即建造器的编译目标（造出来的船与史实舰天然走同一套战斗系统）。排在 Phase 06。

## 当前已完成的技术基础

- **确定性战斗模拟引擎**：固定步长、命名随机流、事件日志；同一 seed 的完整战斗可逐字节重放，是将来多人同步的技术前提；
- **穿深/弹道校准体系**：对官方射表 12 点回归全通过，校准报告作为 CI 合并门禁；
- **模块化损伤链**：分段 + 舱室部件 + 舰员 + 七类伤害通道统一账本 + 起火/进水/损管/殉爆/倾覆/沉没，全部有行为级验收测试在真实对局中断言发生；
- **真实舰船数据与模型管线**：自研 War Thunder 客户端解包 → 参数提取（2,322 舰）→ 模型转换（23 舰 4 级 LOD + 炮塔挂点）全链路，转换器输入=用户自有客户端；
- **3D 前端**：Godot 4 + C#，直接复用战斗引擎；视觉与命中判定三分离（视觉网格永远不是命中依据）；
- **玩家/AI 同接口**：双方产出同一批指令对象，AI 无特权；
- **质量防线**：136 项快速测试（秒级）+ 六档分层测试体系 + CI 三道门禁（快速+集成 / 黄金文件确定性回归 / 性能预算）+ 每晚全量验收；
- **16 份机制决策记录（MDR）**：每个战斗机制"为什么这么做、依据是什么、哪里是近似"全部有审计链。

## 当前已知不足

按对玩家体验的影响排序：

1. **内容薄、模式单一**——主菜单只能进一场固定 1v1；30 艘舰、12 个场景大多够不到；
2. **战斗节奏拖**——画面内固定 1 倍实时速、无加速；当前平衡下 1v1 全 AI 对打常打满 60 分钟平局；
3. **视觉资产差距大**——灰模无贴图、平海面、占位岛屿/飞机、简单特效（详见资产表）；
4. **音效全部为合成占位**，无真实音源、无音乐；
5. **玩家武器面窄**——无鱼雷、无飞机控制、副炮不可独立指挥、无倒车/油门档位、无独立开火键；
6. **AI 只有单舰智能**，无编队战术；AI 动态损管因接线缺陷暂未生效；
7. **四处接线缺陷（2026-10-05 核查新发现，已立项修复）**——炮弹动能小破口进水断线、AI 动态损管失效、防空雷达加成未接、战报伤害统计恒 0；
8. **建造系统零实现**；
9. **内容数量**——1 个机型、1 型鱼雷、无航母、7 艘舰无真实模型；
10. **产品化欠账**——9 月的 1.0.0 安装包已落后 5 个阶段；6v6 仍有偶发长帧/首次模型加载 ~1 秒/艘待打磨。

## 开发路线

依赖链与详细验收标准见 `docs/PROJECT_DESIGN.md` 与 `docs/phases/`：

```text
Phase 00–05 ✅ 已交付（基础/命中几何/3D 骨架/真实资产/机制补全/战术 UI）
   │
   ├─ P04-13 战斗接线缺陷修复（2026-10-05 立项，近期）
   ├─ WS 玩家体验补全（节奏/模式选择/鱼雷/操舰/内容扩录）—— 与下并行
   └─ WS 视觉与音频资产（贴图/击毁态/特效/海面环境/真实音效）—— 与下并行
   │
Phase 06 舰船建造器 → Phase 07 AI 编队与大规模战斗 → Phase 08 产品化（性能/稳定/打包/平衡 → 正式发布）
```

原则：**已完成的 Phase 不回填新任务**；新缺口按性质分流——战斗缺陷进当前战斗阶段，玩法缺口进玩家体验工作流，视觉/音频缺口进资产工作流（其中直接影响观感的贴图与主炮音效优先，装饰性环境靠后），性能打磨归 Phase 08。

## 项目架构概览

```text
第一层：玩家看到的
  3D 海面 + 舰船（真实灰模）+ 曳光弹道 + 火焰烟柱 + 图形 HUD + 战报

第三层：制作工具
  WT 客户端解包与数据提取工具（2,322 舰参数）
  模型格式逆向与批量转换器（BIM2→glTF，23 舰）
  场景配置（12 个战斗场景 JSON）+ 六档测试体系 + 校准/战报工具
```

## 快速开始

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) 与 Godot 4(.NET)（跑前端时）。

```bash
# 构建与快速测试
dotnet build NavyThunder.slnx
dotnet test NavyThunder.slnx --filter "Bucket=Fast"

# 跑一场完整 AI 对战（战报 JSON，同 seed 逐字节可重放）
dotnet run --project src/NavyThunder.SimRunner -- --scenario scenarios/bb_duel.json --out battle-report.json

# 数据集摘要与校准报告（穿深 vs 官方射表回归）
dotnet run --project src/NavyThunder.ProtectionAnalysis -- summary
dotnet run --project src/NavyThunder.ProtectionAnalysis -- report
```

每次 push/PR 由 GitHub Actions 执行：构建 → 快速+集成测试 → 全数据集校验 → 校准报告门禁 → 黄金文件确定性回归 → 性能预算；每晚跑全量验收与 8v8 规模基准。
