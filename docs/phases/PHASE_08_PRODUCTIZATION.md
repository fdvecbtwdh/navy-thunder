# Phase 08 — 性能 / 稳定性 / 产品化

> 状态：`[PLANNED]`
> 前置依赖：Phase 01–07 全部或按范围裁剪（本阶段可分轮：每完成一批内容阶段做一次轻量产品化轮）。

## 1. 阶段目标
把"功能齐"变成"产品稳"：性能达标、长期稳定、崩溃可溯、打包发布、平衡收敛。

## 2. 当前基础（Level A）
headless 性能预算在 CI（6v6 ≥1× Release，实测 ~40×）；2h soak 714 轮 PASS（headless）；崩溃日志/user 目录（`AppEnv`）；打包脚本 `tools/package_release.sh`（1.0.0 已验证干净环境出包）；上一轮发布遗留：前端逐帧性能未验证、平衡 pass 未做、正式 tag 流程未走完（RELEASE_CHECKLIST RC2 未勾项）。

## 3. 外部参考
PROJECT_DESIGN §13 测试体系；1.0 发布流程经验（ROADMAP R4/R5）。

## 4. 不做什么
新玩法机制；内容扩录（归 W3 并行流）。

## 5. 任务与技术设计

| # | 任务 | 验收要点 |
|---|---|---|
| P08-1 | **性能门禁** | 60fps @ 6v6+全武器+特效（Godot headless 基准+profile）；加载 <30s；不达标→优化轮（Instancing/LOD/粒子预算/模拟节流） |
| P08-2 | **3D Soak** | 2h 前端连续运行（复用 soak.sh 思路）：无泄漏（RSS 曲线）、无崩溃、帧率不衰减 |
| P08-3 | **崩溃与日志** | 崩溃率与留痕复核（AppEnv crash/）；玩家可读错误弹窗（非静默退出） |
| P08-4 | **平衡 pass** | AI 对战胜率/时长分布统计（批量 headless，战绩矩阵）；4 阵营同 BR 强度收敛；散布/段 HP/TDS 等 calibration 参数调平 |
| P08-5 | **Release 构建** | 裁剪/AOT 评估；独立可执行；版本/配置/用户目录齐备 |
| P08-6 | **打包与干净环境验证** | zip；无开发环境机器全链路（沿 RC2 方法）；授权审计复核（含新增资产来源） |
| P08-7 | **发布** | 版本号、tag、变更日志、Release Gate 重跑（沿 RELEASE_CHECKLIST 格式新立 1.x 门禁表） |

## 6. 文件修改范围
`tools/`（soak/打包脚本扩展）、CI workflow（加 3D 冒烟+性能 job）、`frontend/Godot/`（性能优化点）、`data/calibration/`（平衡参数）、`docs/`（门禁表）。

## 7. 依赖 / 并行
依赖各内容阶段；P08-4 平衡依赖 P07 AI 稳定。

## 8. 风险
| 风险 | 对策 |
|---|---|
| 60fps 不达 | 优先模拟侧节流与渲染侧 LOD 两级预算拆分；早 profile 常态化（Phase 02 起基线） |
| 平衡与机制改动互相踩 | 平衡只动 calibration 数值，不动结构（结构改动回对应 Phase） |
| Soak 泄漏难定位 | 事件日志/特效池/FX 游标为历史泄漏点（R1.6 经验），优先审查 |

## 9. 测试
CI 常绿定义扩展：构建 → 全测试 → 数据校验 → 校准门 → 黄金门 → 性能门 → 3D 冒烟。Soak 报告入 artifacts。

## 10. 验收标准（PASS/FAIL）
- PASS：60fps 门禁在 CI 常绿（6v6 标准场景）。
- PASS：2h 3D soak 零崩溃零泄漏（RSS 回落）。
- PASS：批量 AI 对战统计（≥200 场）胜率分布落在设计区间（平衡目标文档化）。
- PASS：干净环境安装→完整一场→战报→退出，零人工干预（录屏/截图留证）。
- PASS：授权审计表更新（含 Phase 03 资产来源假设）。
- PASS：新版本 tag + Release 发布完成，Gate 表逐项勾选（只如实标，不复刻 1.0 的 🟡 混淆）。

可安装、可长期游玩、可持续迭代的产品基线；进入下一内容轮（航母系统/顶点编辑/导弹闭环等 Post-1.x 清单）。
